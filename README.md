## Learning Approach

I follow [roadmap.sh/javascript](https://roadmap.sh/javascript) to decide what to learn next and in what order. For each topic I combine several sources to get a complete picture.

| Source | Purpose |
|---|---|
| [roadmap.sh](https://roadmap.sh/javascript) | Topic selection and learning order |
| [MDN Web Docs](https://developer.mozilla.org) | Official reference and deep technical detail |
| [W3Schools](https://www.w3schools.com/js) | Quick examples and syntax lookup |
| [javascript.info](https://javascript.info) | Structured explanations with examples |
| Claude (AI) | Concept clarification, debugging, and practice tasks |

Once a topic is understood, I write the code myself, predict the output before running it, and finish with a small task before moving on.

<br />

## How Every Topic Is Structured

```text
Concept file  ->  Predict the output  ->  Run and compare  ->  Task  ->  Mini project
```

- **Concept file:** explains how the feature works, with inline comments on the reasoning.
- **Predict first:** each result is written as a guess before the code is executed. A wrong guess is the best learning moment.
- **Task:** a hands-on exercise that uses the concept in a realistic situation.
- **Mini project:** a small program that combines the concept with earlier ones.

Comment markers used across the files:

| Marker | Meaning |
|---|---|
| `//!` | Section or topic heading |
| `//?` | Explanation, rule, or reasoning |

## Linting with ESLint

The repo uses ESLint with the `eqeqeq` rule, so loose comparisons (`==`, `!=`) are flagged automatically. Files inside `Equality Comparisons/` use `==` on purpose to demonstrate coercion, so ESLint reports errors there by design.

```bash
# One-time setup
npm install

# Lint a single file
npx eslint "Equality Comparisons/practicleguidelines.js"
```

| Mode | Behaviour |
|---|---|
| `["error", "always"]` | `==` and `!=` are never allowed, `== null` included |
| `["error", "always", { null: "ignore" }]` | Only `== null` and `!= null` are allowed |

> On Windows PowerShell, if `npm` is blocked by the execution policy, run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once and reopen the terminal.
